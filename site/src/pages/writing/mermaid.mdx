# Mermaid Diagrams [Compile diagrams from text to SVG at build time]

## Usage

Write Mermaid syntax inside a `mermaid` code block:

````mdx
```mermaid
graph LR
  A[Client] --> B[Vite]
  B --> C[Waku]
  C --> D[MDX]
  D --> E[HTML]
```
````

Vocs compiles the block to an SVG diagram at build time with [Ondine](https://ondine.sh). Pages ship the SVG, not a diagram renderer, and the diagram follows the light/dark color scheme:

```mermaid
graph LR
  A[Client] --> B[Vite]
  B --> C[Waku]
  C --> D[MDX]
  D --> E[HTML]
```

## Supported Diagrams

Ondine accepts the same syntax as Mermaid, including:

- **Flowcharts** (`graph`, `flowchart`)
- **Sequence diagrams**
- **Class diagrams**
- **State diagrams**
- **Entity-relationship diagrams**
- **Gantt charts**
- **Pie charts**
- **Git graphs**
- **Mindmaps**
- **Timeline**
- **Quadrant charts**
- **C4 diagrams**

See the [Mermaid documentation](https://mermaid.js.org/intro/) for the syntax reference, and the [Ondine documentation](https://ondine.sh) for every supported diagram type.

## Theming

Each diagram reads its colors, font, corners, and strokes from `--ondine-*` CSS custom properties. Vocs sets the colors and font from its theme, so diagrams match the page in both color schemes. Override any property in your `_root.css`:

```css [src/pages/_root.css]
/* Rounds node corners and draws thinner strokes */
.ondine {
  --ondine-radius: 6px;
  --ondine-stroke: 1.5px;
}
```

See [Ondine theming](https://ondine.sh/docs/guides/theming) for the full list of properties.

## How It Works

The remark pipeline replaces each `mermaid` code block with a `<div class="ondine-diagram">` that contains the compiled `<svg>`. No diagram code runs in the browser. Markdown exports, such as per-page `.md` files and `llms.txt`, keep the original `mermaid` code block.

A diagram that fails to compile stops the build with an error that names the file, line, and column.
